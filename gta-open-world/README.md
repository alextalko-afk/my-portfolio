# GTA Open World (prototype)

A code-first, GTA-inspired open world slice built in **Unreal Engine 5.3**
(C++). One drivable car, one on-foot character, a procedurally generated
city you can walk or drive around, and a day/night cycle — everything
built from primitives and runtime-generated textures, the same
"no external assets" philosophy as this repo's `aim-trainer` project.

It is **not** a GTA 6 recreation — that's an AAA-studio-scale project.
This is the "world + car + character" vertical slice: enough to walk out
of a procedurally generated city block, get in a car, and drive around.

## Read this first: how this project was built

This was written entirely as C++ text files in a headless environment
with **no Unreal Editor, no compiler, and no GPU available** — it could
not be opened, compiled, or run while being written. That's a real
constraint worth naming plainly: unlike a scripting-language project
(GDScript, Python, JS) where a mistake is just a runtime error, C++
against the UE5 API needs to *compile* first, and a handful of API calls
below were written from memory rather than verified against a live
engine. Expect to fix a small number of compile errors on first build —
see "Most likely rough edges" below for exactly where to look.

This tradeoff was chosen deliberately over the alternative (Godot or a
browser/Three.js prototype) after being asked to target Unreal Engine 5
specifically. Godot code can be authored just as blind but is plain-text
GDScript with a much smaller/steadier API surface; UE5 C++ is a
meaningfully higher-risk bet without a compiler in the loop, made with
that understood.

## One-time editor setup (~2 minutes)

Two things in Unreal are binary assets (materials, levels) that can't be
authored as text, so unlike everything else in this project they can't be
generated by code. Do these once after opening the project:

1. **Install Unreal Engine 5.3** (or close to it — see "Engine version"
   below) and open `GTAOpenWorld.uproject`. It has C++ source and no
   compiled binaries, so Epic Games Launcher / the editor will offer to
   build it first — accept that (or right-click the `.uproject` →
   *Generate Visual Studio project files* on Windows, then build from
   your IDE, if you'd rather build outside the editor).
2. **Create one material**: Content Browser → right-click → *Material*,
   name it `M_Procedural`, save it to `Content/Materials/`. Open it, add
   a **Texture Sample Parameter 2D** node, name the parameter
   `BaseTexture`, and wire its RGB output to *Base Color*. Save. Every
   surface in this project (roads, buildings, car paint, character) is a
   dynamic instance of this one material with a runtime-generated
   texture plugged into `BaseTexture` — nothing else to do here.
3. **Create one empty level**: File → New Level → *Empty Level*, save it
   as `Content/Maps/OpenWorld`. `Config/DefaultEngine.ini` already points
   `GameDefaultMap`/`EditorStartupMap` at this path, so it should open
   automatically next time — if not, set it manually in *Edit → Project
   Settings → Maps & Modes*.

Press **Play**. `GTAOpenWorldGameMode` builds the entire city, sky, and a
parked car from code on `BeginPlay` — the empty level stays empty in the
editor; everything appears at runtime.

### Engine version

Targets **5.3**. Newer 5.x should mostly work (this is fairly standard
Actor/Component C++ with no exotic APIs), but Chaos/Enhanced Input/Nanite
defaults have shifted release to release — if you're on a notably
different version and hit errors, that's the first thing to suspect.

Walk up to the red car and press **E** to get in; press **E** again while
driving to get out.

## What's implemented

- **Procedural city**: a configurable grid of blocks (default 6×6, 40m
  each), each with a road, sidewalk, and a building with a randomized
  footprint, height (2-14 floors), wall color, and a unique per-building
  window-lit facade texture — all generated at runtime, no imported
  meshes or textures (`ProceduralCityGenerator`, `ProceduralMeshUtils`,
  `ProceduralTextureLibrary`).
- **On-foot character**: third-person camera, walk/sprint/jump, a
  primitive-built (non-skeletal) block-out figure.
- **Drivable car**: arcade-style acceleration/braking/steering with a
  chase camera, collides with the city instead of driving through it.
- **Enter/exit**: walk up to a parked car and press E to drive it; press
  E again to get out beside it. Orchestrated centrally by
  `OpenWorldPlayerController` (see the comment at the top of that class
  for why it isn't split across the two pawns).
- **Day/night cycle**: the sun rotates on a configurable real-time
  period, warming in color near the horizon; the sky light recaptures
  periodically so ambient lighting tracks it.
- **Everything generated at runtime**: consistent with `aim-trainer`,
  there are no imported textures or meshes — geometry comes from
  `ProceduralMeshComponent`, art comes from hand-rolled pixel buffers
  turned into `UTexture2D` at runtime.

## Known limitations / deliberate scope cuts

- **Arcade driving, not Chaos Vehicles**: real wheel physics (suspension,
  per-wheel friction) needs a `UChaosWheeledVehicleMovementComponent`
  with a wheel-class setup that's easy to misconfigure and impossible to
  tune without driving it. `ArcadeVehicle` instead applies acceleration/
  steering directly to the actor transform — less realistic, far more
  likely to just work. Swapping in real vehicle physics later is a
  contained change (one class).
- **Block-out character and car, not skinned meshes**: a real animated
  character needs a skeletal mesh + animation blueprint, both authored
  visually in-editor. The character and car are primitive shapes
  (cylinders/spheres/cubes from `/Engine/BasicShapes/`), the same
  "procedural rig" approach `aim-trainer`'s enemies use.
- **One shared material**: every textured surface reuses the single
  `M_Procedural` dynamic-instance pattern rather than per-surface
  hand-authored materials (roughness maps, normal maps, etc.) — flat but
  fully proceduralized.
- **No traffic, pedestrians, missions, or weapons** — out of scope for
  this slice; `World`/`Characters`/`Vehicles`-style separation in
  `Source/GTAOpenWorld/` leaves room to add them later without a rewrite.
- **Interaction uses distance polling, not overlap events**: simpler and
  fewer blind assumptions about collision channel setup than trigger
  volumes, at a trivial cost given there's one car.

### Most likely rough edges on first compile

Named here specifically because they couldn't be checked against a
running engine:

- `ProceduralCityGenerator.cpp` / `FinalizeSection()`: calls
  `UProceduralMeshComponent::CreateMeshSection_LinearColor()` with a
  single UV channel. Some UE5 versions only expose the 4-UV-channel
  overload (`UV0, UV1, UV2, UV3`) — if this doesn't compile, pass
  `MeshData.UVs` as `UV0` and empty `TArray<FVector2D>{}` for the rest.
- `ProceduralMeshUtils.cpp`: box faces might render back-face-culled
  (invisible from outside) if this engine version's front-face winding
  convention differs from what's assumed here — if buildings look
  inside-out, swap the `(0,1,2)/(0,2,3)` triangle index order in
  `AppendQuad()`.
- Anywhere a `LoadObject<UMaterialInterface>(nullptr,
  TEXT("/Game/Materials/M_Procedural.M_Procedural"))` call resolves to
  `nullptr` at runtime, it means step 2 of the one-time setup above
  wasn't done (or the material was saved somewhere else) — affected
  surfaces fall back to the engine's default grey material rather than
  crashing, and `ProceduralCityGenerator` prints an on-screen reminder.

## Project structure

```
GTAOpenWorld.uproject
Config/
  DefaultEngine.ini    -- default map + GameMode wiring
  DefaultGame.ini
  DefaultInput.ini      -- classic Action/Axis input bindings (not Enhanced
                            Input - that needs editor-authored Input Action
                            assets, which hit the same "can't author binary
                            assets blind" wall as materials/levels)
Source/
  GTAOpenWorld.Target.cs / GTAOpenWorldEditor.Target.cs
  GTAOpenWorld/
    GTAOpenWorld.Build.cs
    GTAOpenWorldGameMode.*        -- spawns city/sky/car, places the player
    OpenWorldPlayerController.*   -- enter/exit vehicle possession swap
    OpenWorldCharacter.*          -- on-foot pawn
    ArcadeVehicle.*               -- drivable car
    ProceduralCityGenerator.*     -- ground, roads, per-block buildings
    ProceduralMeshUtils.*         -- box/quad geometry builders
    ProceduralTextureLibrary.*    -- runtime UTexture2D generation
    DayNightCycle.*               -- rotating sun + sky recapture
```
